**Round-2 review findings (CodeRabbit and an independent adversarial-review agent, both reproduced, fixed):**

- **P2 (both sources, independently)**: `build_observed_effect_for_construction_commit`'s `has_evidence` check only proved the target branch NAME existed (`branch in list_branches(rig)`), never that it actually pointed at `landed_sha` — a genuine child-of-`expected_head` commit landing on a DIFFERENT ref while the checked branch stayed unmoved still reported `has_evidence=True`, letting a clean Effect Census attribute a mutation to a branch that never received it. Fixed by resolving the branch's own real current head (`rig.transport.resolve_ref`) and requiring it to equal `landed_sha` exactly, with a new permanent regression test reproducing the exact scenario.
- **P3 (independent adversarial review)**: `build_live_construction_dispatch`'s `resource` parameter was declared but never read — dead code left over from mirroring `repository_construction_facility._dispatch`'s own signature. Removed.
- **Minor (CodeRabbit)**: this doc's own Owner-authorization paragraph claimed the disclosure is folded into `AuthorityTransferRecord.stabilization_evidence["observer_predicates"]` — but the record never actually populated that category. Fixed by genuinely populating `observer_predicates`.

**Round-3 review findings (Codex, all four reproduced and fixed) — these went to the actual integrity of the mechanism, not surface bugs, and materially changed this slice's own honest result:**

- **P1: assurance routing under-specified.** The policy routed every obligation to `("sergeant",)` only — copied from an isolated unit-test fixture pattern, never meant to represent a real authority change. The real, frozen Assurance Matrix (`docs/02-assurance-matrix.md`, Generation 1) is explicit: "Change to Tenfold authority... — Tenfold Council + independent authority review; Owner approval where authority policy changes." Fixed by routing to `("sergeant", "tenfold_council")` and genuinely building `run_g2_28_council_review()` — a real invocation of `council_pin.invoke_pinned_council`, the first real (non-test) call site of that machinery anywhere in Gen2. Disclosed openly (in the policy's own code comment): Council's own invocation is treated as satisfying both "Council" and "independent authority review" together, since Council is the established independent-review body Gen2 already uses elsewhere in this project for that role — a genuinely open scope question, not silently assumed, since no other real Gen2 code has needed to resolve it either. The Matrix's own `assurance_matrix_digest` binding remains a placeholder (`"m" * 64`) — disclosed as a pre-existing, project-wide gap (`proof_transfer.py`, the only other real, non-test module building a `ConstitutionalPolicySet`, uses the identical placeholder), not something this slice invents or attempts to close on its own.
- **P1: verdict/eligibility conflation.** `AssuranceBindingClaim` carries no verdict/eligibility field — `compute_proof_verdict`'s own reconciliation only checks that the two independent copies genuinely agree with each other, never whether the verdict was actually a pass. The original code handed it a claim unconditionally, so Sergeant's genuine `NEEDS_WORK` silently counted as "satisfied." Fixed by gating claim construction on `eligible_for_satisfaction` (both independent copies, for both Sergeant and Council) — when not eligible, the assurance type is simply absent from what's handed to `compute_proof_verdict`, so `required_assurance <= satisfied_assurance` correctly fails.
- **P1: no write-ahead journaling before the real mutation.** `create_branch`/`commit` ran with no verified durable Chronicle intent recorded first — a crash mid-mutation on the real repository would leave no authoritative record to reconcile occurrence against. Fixed with a real Chronicle log (`chronicle_bridge.open_chronicle`/`append_entry`, the same real compiled Rust engine `authority_transfer.py`'s own G2-21 pattern uses): a genuine "intent" entry appended before either mutation, a "completed" entry appended only after both genuinely succeeded.
- **P1: Effect Census only checked the one expected branch.** A concurrent or induced mutation to any OTHER branch would never enter the census at all, since both `expected` and `observed` were built solely for the producer-declared target. Fixed with `build_unexpected_branch_effects()`: every branch's head is captured before the mutation and re-enumerated after, so any branch other than the target that changed unexpectedly enters the census as genuine, unattributed residue — matching SC-23's own established `list_branches` enumeration-completeness precedent.
