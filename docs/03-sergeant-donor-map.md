# Sergeant Donor Map

Tenfold uses Sergeant as the primary organisational donor. This document prevents future implementations from either ignoring that donor or cloning Sergeant wholesale.

## What Tenfold inherits

### Shared training, unequal authority

All ranks share foundational discipline, but authority does not flatten.

Tenfold adopts:

- trained bounded workers;
- explicit rank/authority boundaries;
- permanent specialist responsibility;
- evidence obligations;
- stop conditions;
- escalation rather than self-promotion;
- models as optional capabilities, not ranks.

### Command and rebrief discipline

Tenfold adopts the structural pattern:

```text
command authority
  -> field coordination
  -> permanent specialists
  -> bounded workers
  -> evidence
  -> council/rebrief
  -> next command state
```

### Council principle

Tenfold adopts Sergeant's key epistemic rule:

> Completed work is not automatically correct work.

A Milestone Council reconciles the ground picture before the next dependent frontier is released.

### Evidence over votes

Tenfold does not use raw worker majority. Direct reproducible contradictory evidence may outweigh many correlated confirmations.

### Model-free normal path

Tenfold must remain operational when every model route is unavailable. Optional consultant models amplify difficult reasoning only.

## What Tenfold does not copy

Tenfold is not a fork/rebrand of Sergeant.

It does not copy Sergeant's product purpose as a software review system, learning system, or final review authority.

Tenfold does not require Sergeant's exact officer names. It preserves the structural principle while defining execution-specific permanent responsibilities.

Tenfold does not turn Sergeant into a Private. When the Assurance Matrix requires Sergeant consultation, Sergeant remains an independent assurance system and returns its own review evidence under its own authority.

## Founding relationship

```text
Sergeant
  donor: command/training/council/evidence discipline

Tenfold
  product: mass safe machine execution of approved roadmaps
```

The donor relationship is architectural evidence, not runtime dependency. Tenfold's deterministic core must not require Sergeant to be online.

## Implementation rule

Before inventing a new Tenfold mechanism for worker rank, training, evidence escalation, Council/rebrief, or model-support authority, check whether Sergeant already solved the underlying discipline. Reuse the proven principle where compatible; do not introduce a generic autonomous-agent pattern that weakens the donor model.
